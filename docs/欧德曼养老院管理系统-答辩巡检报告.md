## 1. 整体功能总览

欧德曼养老院管理系统定位为养老院入住、照护、费用、家属协同和后台运营管理系统。当前代码已经形成“公开端提交申请/注册 -> 管理员审核和办理 -> 护理员执行服务 -> 家属查看与发起申请 -> 管理员审批和维护”的主业务闭环。

系统解决的问题：

- 入住申请、老人档案、家属绑定和正式入住分散的问题。
- 房间、床位、入住登记和床位状态需要联动的问题。
- 护理员服务对象需要明确分配，避免全院数据暴露的问题。
- 家属只能查看绑定老人，不能直接修改正式档案的问题。
- 护理记录、健康监测、用药执行、费用账单和缴费登记需要可追溯的问题。
- 图片资源需要统一上传、管理、展示和兜底的问题。
- 公益赞助需要前台展示和后台维护的问题。

## 2. 角色关系梳理

### 管理员

管理员账号来自 `xitong_yonghu`，通过 `yonghu_juese` 关联 `xitong_juese.juese_bianma = admin`。管理员负责入住申请审核、正式入住、老人档案维护、床位管理、护理员和护理项目配置、审批、费用、赞助、图片和系统用户角色管理。

### 护理员

护理员登录用户在 `xitong_yonghu` 中，角色编码为 `huli`。护理员业务身份在 `huli_renyuan`，通过 `huli_renyuan.yonghu_id = xitong_yonghu.id` 绑定。护理员服务老人由 `renyuan_laoren` 分配，状态为 `服务中` 的记录才是当前服务范围。

护理员只能看自己服务的老人，不只是前端隐藏菜单。后端 `HuliyuanYewuBizImpl` 会先通过当前登录用户找到护理员 ID，再用 `renyuan_laoren` 校验 `countFuwuLaoren`，未分配老人会返回“只能操作自己负责的老人”。

### 家属

家属登录用户在 `xitong_yonghu` 中，角色编码为 `jiashu`。家属业务信息在 `jiashu_xinxi`，当前代码通过手机号绑定登录用户和家属记录：`jiashu_xinxi.shouji = xitong_yonghu.shouji`。家属绑定老人由 `jiashu_xinxi.laoren_id` 指向 `laoren_xinxi.id`。

家属只能看绑定老人。后端 `JiashuYewuBizImpl` 对查看、申请、头像上传和费用查询都调用 `requireBangding` 或 `requireBangdingIfPresent`，未绑定老人会返回“只能查看或操作自己绑定的老人”。

### 老人

老人主数据在 `laoren_xinxi`。老人和家属是 `laoren_xinxi.id -> jiashu_xinxi.laoren_id`；老人和护理员是 `laoren_xinxi.id -> renyuan_laoren.laoren_id -> huli_renyuan.id`。

## 3. 业务流程梳理

### 3.1 对外首页流程

前端页面：`oldman1/src/views/duiwai/DuiwaiShouye.vue`  
相关图片：`/uploads/home/banner-*.jpg`、`/uploads/environment/*.jpg`  
入口：`/`、`/zhuce`、`/ruzhu-shenqing`、`/zanzhu`、`/denglu`

首页轮播图是前端固定数组读取 `/uploads/home/banner-1.jpg` 到 `/uploads/home/banner-3.jpg`，每 5 秒切换；环境图是前端固定数组，点击缩略图切换大图；环境图有 `/uploads/default/room-default.jpg` 兜底。

### 3.2 家属注册流程

| 环节 | 文件/对象 |
| --- | --- |
| 前端页面 | `src/views/duiwai/Zhuce.vue` |
| 前端接口 | `src/api/gongkai.js` -> `jiashuZhuce` |
| 后端 Controller | `GongkaiController.jiashuZhuce` |
| Biz | `GongkaiBizImpl.jiashuZhuce` |
| Mapper | `GongkaiMapper.insertLaoren / insertYonghu / insertYonghuJuese / insertJiashu` |
| 表 | `laoren_xinxi`、`xitong_yonghu`、`yonghu_juese`、`jiashu_xinxi` |

注册会创建一条老人档案，默认 `ruzhu_zhuangtai = 未入住`，再创建家属登录用户，分配 `jiashu` 角色，并写入家属绑定关系。注册页当前没有背景图，使用 CSS 渐变背景；滑块验证码由前端组件完成。

### 3.3 在线入住申请与审核流程

公开页面 `RuzhuShenqing.vue` 调用 `/gongkai/ruzhu-shenqing-add`，写入 `ruzhu_shenqing`，默认 `shenqing_zhuangtai = 待审核`，`banli_zhuangtai = 未办理`。

管理员页面 `RuzhuShenqingShenhe.vue` 调用 `/admin/ruzhu-shenqing/*`。审核通过后：

- 更新申请状态为 `已通过`。
- 查找或创建 `laoren_xinxi`。
- 创建或更新 `jiashu_xinxi`。
- 将 `ruzhu_shenqing.laoren_id` 关联到老人。
- 不直接分配床位，不直接写 `ruzhu_dengji`。

这样做的原因是：审核只确认入住资格和基础资料，正式入住还要选择实际房间、空闲床位、入住日期、合同到期和押金。

### 3.4 正式入住流程

管理员在 `RuzhuDengji.vue` 从已通过未办理申请带入资料，选择房间和空闲床位，调用 `/laoren-xinxi/ruzhu`。后端 `LaorenXinxiBizImpl.ruzhu` 会：

- 校验当前用户是管理员。
- 校验老人不是在住、外出、退住状态。
- 校验 `chuangwei_xinxi.zhuangtai = 空闲`。
- 写入 `ruzhu_dengji`。
- 写入 `chuangwei_shiyong`，状态为 `正在使用`。
- 将床位状态改为 `有人`。
- 将老人状态改为 `在住`。
- 如果来自申请，将 `ruzhu_shenqing.banli_zhuangtai` 改为 `已办理`。

### 3.5 床位管理流程

前端：`ChuangweiFenpei.vue`  
接口：`chuangwei.js`  
后端：`FangjianController`、`ChuangweiController`、`ChuangweiBizImpl`、`ChuangweiMapper.xml`  
表：`fangjian_xinxi`、`chuangwei_xinxi`、`chuangwei_shiyong`

只能选择空闲床位由后端 `countKongxianChuangwei` 保证。分配床位会新增使用记录并改老人状态为在住；调换床位会结束旧使用记录、释放旧床位、占用新床位；释放床位会结束使用记录、床位改空闲、老人改退住。

### 3.6 护理员管理流程

前端：`HuliRenyuan.vue`  
接口：`huli.js`  
后端：`HuliRenyuanController`、`HuliRenyuanBizImpl`、`HuliRenyuanMapper.xml`  
表：`huli_renyuan`、`renyuan_laoren`

管理员维护护理员，给护理员分配服务老人。重复分配由 `countServingAssignment` 拒绝。护理员登录后只通过 `renyuan_laoren` 查询自己服务范围内的数据。

### 3.7 护理项目与护理级别流程

前端：`HuliXiangmu.vue`  
接口：`huliguanli.js`  
后端：`HuliXiangmuController`、`HuliJibieController`、`LaorenHuliController`  
表：`huli_xiangmu`、`huli_jibie`、`jibie_xiangmu`、`laoren_huli`

管理员维护护理项目和护理级别，护理级别绑定多个护理项目，老人通过 `laoren_huli` 设置当前护理级别。护理员新增护理记录时，后端校验护理项目必须属于老人当前护理级别。

### 3.9 家属端业务流程

前端：`LaorenXinxi.vue`、`HuliJilu.vue`、`JiankangYongyao.vue`、`Feiyong.vue`、`Shenqing.vue`  
接口：`jiashu.js`  
后端：`JiashuYewuController`、`JiashuYewuBizImpl`、`JiashuYewuMapper.xml`

已实现内容：

- 查看绑定老人。
- 查看床位、护理记录、健康监测、用药计划、服药记录。
- 查看费用账单和缴费记录。
- 提交外出申请。
- 提交退住申请。
- 提交老人信息修改申请。

家属不能直接修改正式老人档案。当前页面提供的是“申请修改”，数据先进入 `laoren_xinxi_xiugai_shenqing`，管理员审核通过后才更新 `laoren_xinxi`。代码里还存在 `laoren-touxiang-upload` 直接上传接口，但当前家属页面实际使用的是变更申请头像上传，不建议作为演示重点。

### 3.10 老人信息变更审核流程

当前已实现。  
家属端：`LaorenXinxi.vue` -> `addJiashuLaorenXiugaiShenqing`、`uploadJiashuLaorenXiugaiTouxiang`  
管理员端：`LaorenXiugaiShenqing.vue` -> `/admin/laoren-xiugai-shenqing/*`  
表：`laoren_xinxi_xiugai_shenqing`

审核通过时 `AdminLaorenXiugaiShenqingBizImpl.pass` 调用 `updateLaorenXinxi`，更新正式老人档案的联系电话、家庭住址、备注和头像。审核驳回只更新申请状态，不修改正式档案。

### 3.11 外出退住审批流程

申请来源：

- 家属端 `/jiashu/waichu-add`、`/jiashu/tuizhu-add`
- 护理员端 `/huliyuan/waichu/add`、`/huliyuan/tuizhu/add`

管理员审批：

- `/admin/shenpi/waichu-pass` 通过外出，老人状态改 `外出`，当前床位改 `外出`。
- `/admin/shenpi/waichu-huiyuan` 登记回院，老人状态恢复 `在住`，床位恢复 `有人`。
- `/admin/shenpi/tuizhu-pass` 通过退住，床位改 `空闲`，结束 `chuangwei_shiyong` 当前记录，老人状态改 `退住`。

### 3.12 费用账单和线下缴费流程

前端：`admin/Feiyong.vue`、`jiashu/Feiyong.vue`  
后端：`AdminFeiyongController`、`AdminFeiyongBizImpl`、`AdminFeiyongMapper.xml`  
表：`feiyong_zhangdan`、`jiaofei_jilu`

管理员生成费用账单，系统按床位费、护理费、药品费、其他费用合计 `zongjine`。管理员登记线下缴费后，账单状态按已缴金额计算为 `待缴费`、`部分缴费`、`已结清`。家属端只读。当前代码没有在线支付，也没有继续展示缴费凭证，适合说明为项目边界：线下收款登记，不接入第三方支付。

### 3.13 公益赞助流程

前台：`Zanzhu.vue`，读取 `/zanzhu/gongkai-list`、`/zanzhu/yongtu-list`、`/zanzhu/wuzi-list`。  
后台：`ZanzhuGuanli.vue`，维护赞助人、赞助记录、物资捐赠、赞助用途、赞助意向。  
表：`zanzhu_ren`、`zanzhu_jilu`、`wuzi_juanzeng`、`zanzhu_yongtu`、`zanzhu_yixiang`。

当前前台展示实际使用赞助人头像 `zanzhu_ren.touxiang_url`，兜底 `/uploads/zanzhu/donor-default.jpg`。物资图片、凭证图片等字段在数据库存在，但当前前台列表主要是文字展示，不作为演示重点。系统只收集赞助意向，不做在线支付和二维码支付。

## 7. 图片上传和默认图机制专题

### 后端机制

- `WebConfig.java` 将 `/uploads/**` 映射到仓库根目录下的 `uploads/`（可用环境变量 `OLDMAN_UPLOAD_DIR` 覆盖）。
- `WenjianController.java` 提供 `/admin/wenjian/image-list`、`upload-image`、`replace-image`、`delete-image`。
- `WenjianBizImpl.java` 限制类型为 `home`、`environment`、`login`、`zanzhu`、`avatar`、`default`、`captcha`。
- 文件大小限制 5MB，扩展名允许 `jpg`、`jpeg`、`png`、`webp`。
- 上传文件使用 UUID 文件名保存，返回 `/uploads/{type}/{filename}`。
- 替换图片保留旧文件名覆盖内容。
- 删除图片直接删除对应文件。
- 管理接口后端校验管理员角色。

### 前端机制

- `wenjian.js` 封装图片管理接口。
- `TupianGuanli.vue` 支持图片列表、类型筛选、关键词搜索、上传、替换、预览、删除。
- `tupianBanben.js` 用 localStorage 维护图片版本号，上传/替换/删除后让前台图片 URL 带版本参数刷新缓存。
- `DuiwaiShouye.vue` 固定读取首页轮播和环境图。
- `Denglu.vue` 固定读取 `/uploads/login/login-bg.jpg`。
- `Zhuce.vue` 当前不使用注册背景图，`/uploads/login/register-bg.jpg` 存在但不是当前演示重点。
- `HuakuaiYanzheng.vue` 固定读取 `/uploads/captcha/captcha-1.jpg` 到 `captcha-3.jpg`。
- 老人头像在管理员、护理员、家属页面使用 `laoren_xinxi.touxiang`，空值或加载失败时兜底 `/uploads/avatar/user-default.jpg`。

## 10. 答辩推荐演示顺序

1. 对外首页：轮播、环境图点击切换、登录/注册/入住申请/赞助入口。
2. 家属注册：展示注册表单和滑块验证码，说明会创建家属账号和未入住老人档案。
3. 在线入住申请：游客提交入住申请，进入待审核。
4. 管理员审核入住申请：通过后创建/关联老人和家属，但不直接入住。
5. 正式入住登记：从已通过申请带入资料，选择空闲床位，完成入住。
6. 床位管理：展示床位状态，说明空闲、有人、外出、释放联动。
7. 护理员分配老人：管理员给护理员分配服务对象，重复分配被拦截。
8. 护理员登录：只看到自己服务老人，打开老人详情弹窗。
9. 护理记录、健康监测、用药执行：展示护理员端日常业务。
10. 家属登录：查看绑定老人、护理/健康/用药/费用信息。
11. 家属提交外出或退住申请，管理员审批；外出通过后再演示回院恢复。
12. 费用账单和线下缴费：管理员生成账单、登记缴费，家属只读。
13. 老人信息变更申请：家属提交，管理员审核通过后正式档案更新。
14. 公益赞助：前台展示，后台维护赞助人、记录、物资、用途、意向。
15. 图片管理：上传/替换/删除图片，说明 `/uploads` 静态映射和默认图兜底。
16. 系统管理：用户管理、角色分配、启停用户、重置密码；角色启停/删除不作为重点。

## 11. 项目亮点总结

- 三端角色分离：管理员、护理员、家属路由和业务入口清晰。
- 后端数据范围控制：护理员按 `renyuan_laoren`，家属按 `jiashu_xinxi` 绑定关系过滤，不只靠前端菜单。
- 入住申请到正式入住闭环：公开申请、后台审核、正式入住、床位占用分阶段完成。
